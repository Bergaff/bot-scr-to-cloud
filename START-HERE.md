# Как начать работать — по шагам

Инструкция от нуля до рабочего радара: каждый шаг = действие + команда + что ты должен увидеть.
Если что-то пошло не так — в конце есть таблица «что означает ошибка».

Время целиком: **20–25 минут**, из них 10 — первый запуск. Ничего не ломается, если остановиться
на любом шаге и продолжить завтра: сессия и база сохраняются на диске.

Чек-лист в конце — можно идти по нему галочками.

---

## Шаг 0. Что нужно подготовить (5 мин)

| Что | Зачем | Как проверить |
|---|---|---|
| Python 3.10+ | на нём всё работает | `python3 --version` или `python --version` |
| Аккаунт Telegram | чтение чатов идёт от твоего имени | — |
| **Подписка на 10 чатов** (список в `sources.yaml`) | Telegram не даёт читать чаты, где ты не участник | ничего проверять не нужно: если на все подписан — просто запускай. Радар сам напишет по каждому чату, если аккаунт не состоит в нём |
| Доступ к телефону аккаунта | один раз ввести код из Telegram | — |

Про аккаунт: если чаты читает твой основной аккаунт — нормально, риск минимальный (только чтение).
Полностью параноидальный вариант — отдельный аккаунт (вторая SIM/eSIM), но начинать можно и с основного.

## Шаг 1. Установить Python (5 мин)

**Windows:** скачай с [python.org/downloads](https://www.python.org/downloads/), при установке
обязательно поставь галочку **«Add python.exe to PATH»**. Проверка в новом окне терминала:
```bat
python --version
```

**macOS:** `brew install python` (если нет brew — [brew.sh](https://brew.sh)).
**Linux (Ubuntu/Debian):** `sudo apt install python3 python3-venv python3-pip`.

Проверка: команда печатает что-то вроде `Python 3.12.4`.

## Шаг 2. Получить API ID и API hash (5 мин, один раз)

1. Открой https://my.telegram.org и войди номером телефона (код придёт в Telegram).
2. **API development tools** → заполни:
   * App title: `my radar` (любое),
   * Short name: `myradar` (латиницей, 5+ символов),
   * Platform: Desktop, URL и Description можно оставить пустыми.
3. Скопируй **App api_id** (число, например `1234567`) и **App api_hash** (32 символа).

Это ключи приложения, а не пароль от аккаунта. Храни их как пароль: не выкладывай, не показывай
на стримах, не коммить в git.

## Шаг 3. Распаковать проект и поставить зависимости (3 мин)

Скачай из воркспейса `telegram-scraper.zip`, распакуй (например, в `C:\radar\telegram-scraper`
на Windows или `~/radar/telegram-scraper` на mac/Linux) и открой терминал в этой папке.

Ожидаемый результат: в начале строки терминала появилось `(.venv)`, pip отчитался
`Successfully installed telethon-1.45... pysocks... pyyaml...`.

## Шаг 4. Прописать ключи — один раз и навсегда (3 мин)

**Важно про Windows:** `cmd` и PowerShell — разные языки, их команды нельзя смешивать.
Если в чёрном окне (cmd) вставить строку PowerShell, будет ошибка
`Синтаксическая ошибка в имени файла, имени папки или метке тома.`

| Окно | Синтаксис | Живёт |
|---|---|---|
| **cmd** (чёрное окно, `C:\...>`) | `set TG_API_ID=1234567` | только это окно |
| **PowerShell** (синее, `PS C:\...>`) | `$env:TG_API_ID="1234567"` | только это окно |
| **cron/скрипты** | `export TG_API_ID=1234567` | только эта сессия |

### Рекомендую: файл `.env` — вводишь один раз, дальше забыл

1. В папке проекта скопируй файл `.env.example` и переименуй копию в `.env`
   (в проводнике: ПКМ → Копировать, затем ПКМ → Вставить, F2 → `.env`).
   Если Windows не даёт переименовать без имени — сохрани как `.env.` (точка в конце) или открой
   Блокнотом, «Сохранить как» → имя `.env` → тип «Все файлы».
2. Открой `.env` Блокнотом и впиши свои значения (без кавычек, без пробелов вокруг `=`):
```
TG_API_ID=1234567
TG_API_HASH=86e0b1957aaaaaaaaaaaaaaaaaaaaaaaaaaaa
```
3. Сохрани. Всё — дальше просто запускаешь `start.bat`, он сам подхватит ключи, активирует
   `.venv` и при первом запуске поставит зависимости.

Проверка, что ключи видны: `start.bat --doctor` — команда покажет по каждому пункту PASS/WARN/FAIL.

### Если хочешь задать ключи глобально в Windows 10 (для запуска напрямую `python monitor.py`)

**Способ 1, командой (сохраняется навсегда, но не в текущем окне):**
```bat
setx TG_API_ID 1234567
setx TG_API_HASH 86e0b1957aaaaaaaaaaaaaaaaaaaaaaaaaaaa
```
После этого **закрой и открой окно заново** — переменные появляются только в новых окнах.
Проверка: `echo %TG_API_ID%`.

**Способ 2, через интерфейс:** `Win+R` → `sysdm.cpl` → вкладка «Дополнительно» →
«Переменные среды» → в разделе **«Переменные среды пользователя»** → «Создать»:
имя `TG_API_ID`, значение — твой id; так же создай `TG_API_HASH`. Затем новое окно cmd.

⚠️ Ключи должны быть полными: `api_id` — целое число (обычно 7–8 цифр, например `1234567`),
`api_hash` — ровно **32** символа. Обрезанные значения (`37`, `86e0b1957`) не сработают —
`--doctor` такие сразу отловит. Если ты где-то публиковал хеш целиком, зайди на my.telegram.org,
удали приложение и создай новое (старый хеш перестанет действовать).

## Шаг 6. Первый вход и разовый проход по чатам (3 мин)

Если `--doctor` показал «можно запускать» — вот порядок первых трёх команд:

```bat
start.bat --once --catchup 20                        читает последние 20 сообщений в каждом чате и выходит
start.bat --notify console --heartbeat 15            живой режим: уведомления в консоль + пульс раз в 15 мин
start.bat --list-topics                              показать темы форум-чатов и их id
start.bat --export hits.csv                           выгружает найденное в CSV
start.bat --test-notify --notify bot                  проверяет, что уведомление от бота доходит
```

Первый вход лучше делать **вручную** (не через Планировщик задач): Telegram спросит телефон и код.
Если код не приходит — не повторяй запрос, а сразу переходи к разделу «Если код не приходит» ниже:
там вход по QR-коду, без SMS и без кода вообще.

**Если вход уже выполнен** (в терминале было `[+] Вход выполнен …` и создан файл
`monitor_session.session`) — сразу запускай первый проход:

```bat
start.bat --once --catchup 20
```

Что должно произойти:

Если какой-то чат не разрешился (`не смог разрешить @…`), значит аккаунт в нём не состоит —
подпишись с того же аккаунта и повтори. Ноль совпадений — тоже нормально: у тебя ещё нет
истории, радар начнёт ловить новые сообщения сразу после запуска.


Что произойдёт и что ты увидишь по шагам:

## Если код из Telegram не приходит — вход по QR (2 мин)

Сначала пойми, что происходит. Код от Telegram — это **не SMS**, он приходит **сообщением
в приложение Telegram** на уже авторизованном устройстве. Ситуации по частоте:

| Что происходит | Причина | Что делать |
|---|---|---|
| Стоишь и ждёшь SMS, которого нет | у аккаунта уже есть Telegram на телефоне — код ушёл **в приложение**, в служебный чат «Telegram» | открой Telegram на телефоне → чат с галочкой «Telegram» → там код. Если висит вопрос «Подтвердите вход» — нажми «Да, это я», потом жди код |
| Сообщение «код отправлен», но в приложении ничего | телефон в роуминге / без интернета / SMS-роуминг не оплачен (актуально для украинских и других иностранных SIM в Беларуси) | подключи телефон к Wi-Fi — этого достаточно, чтобы сообщение дошло |
| Запросил код 3–4 раза подряд | каждый новый запрос **обнуляет** предыдущий код, дальше Telegram временно перестаёт отправлять | остановись и подожди 15–30 минут, потом используй QR-вход |
| Номер вообще не зарегистрирован в Telegram | кода не будет, нужно сперва создать аккаунт | зарегистрируйся в официальном приложении Telegram (там SMS придёт), затем QR-вход |

**Обход, который работает почти всегда — вход по QR-коду (без кода и без SMS):**

```bat
start.bat --login-qr
```

1. В терминале нарисуется QR (растяни окно, если картинка «ломается»).
2. На телефоне, где Telegram **уже авторизован**: Настройки → Устройства → **Подключить устройство**
   (Settings → Devices → Link Desktop Device) → наведи камеру на QR.
3. В терминале появится `[+] Вход выполнен: …` и файл сессии `monitor_session.session`.
   Если включён облачный пароль (2FA) — скрипт спросит его тут же.
4. Дальше всё как обычно: `start.bat --once --catchup 20` — логин больше не спросят.

*Почему это надёжнее:* QR-вход вообще не использует SMS и код, а опирается на уже работающую
сессию на телефоне. Отдельно удобно, что он не зависит от того, режет ли оператор служебные SMS.
*Ограничение:* нужен аккаунт Telegram на этом номере (пусть даже недавно созданный) и интернет
на телефоне. Если номера в Telegram нет — сначала зарегистрируйся в приложении, потом QR.

## Если Telegram пишет «код введён верно, но правильный пароль не указан»

Это сообщение означает: **код ты ввёл правильно, а облачный пароль (2FA) — нет**.
То есть код до тебя доходит, и аккаунт в порядке — дело только в пароле.

1. **Пароль известен** → просто запусти снова `start.bat --login-qr` (или `start.bat --once`)
   и введи его внимательно. Ввод пароля скрыт, символы не отображаются — это нормально.
   Самая частая причина ошибки: **включённая русская раскладка** (пароль чувствителен к языку
   и регистру) или случайный Caps Lock.
2. **Не помнишь пароль** → сбросить можно только в самом Telegram:
   Настройки → Конфиденциальность и безопасность → **Облачный пароль** → «Забыли пароль?» →
   восстановить по e-mail (если он привязан) **либо подождать 7 дней** (так Telegram защищает
   аккаунт). После сброса/вспоминания снова запусти `start.bat --login-qr`.
3. **Не подбирай пароль перебором.** Telegram ограничивает число попыток (может включиться
   FloodWait на часы), а если включено «самоуничтожение аккаунта» — аккаунт вообще сбросится.
   Скрипт поэтому делает всего 3 попытки и останавливается с инструкцией.

Совет на будущее: если не хочешь возиться с 2FA у рабочего аккаунта — заведи отдельный
аккаунт для радара (вторая SIM/eSIM), включи на нём 2FA и запиши пароль в менеджер паролей.

## Как успеть отсканировать QR (чтобы не ловить AUTH_TOKEN_EXPIRED)

QR-код одноразовый и живёт примерно полминуты-минуту, а после сканирования нужно **успеть нажать
«Подтвердить» на телефоне**. Отсюда ошибка `400 AUTH_TOKEN_EXPIRED`. Что помогает:

1. **Сначала подготовь телефон**, потом запускай скрипт: открой Telegram → Настройки → Устройства →
   «Подключить устройство» — экран должен ждать сканирования ещё до запуска `start.bat --login-qr`.
2. **Растяни окно терминала** пошире и повыше — иначе QR обрежется и камера его не прочтёт.
3. **Сканируй сразу и подтверждай сразу** — не откладывай телефон «посмотреть потом».
4. Если QR в консоли выглядит «рябью» (старый cmd и шрифт Raster) — запусти в ASCII-режиме:
   `start.bat --login-qr --ascii-qr` (или сначала выполни `chcp 65001`).
5. **Скрипт не надо перезапускать.** Он сам обновляет QR каждые ~30–60 секунд и печатает новый:
   `[i] Telegram ответил AUTH_TOKEN_EXPIRED … Выдаю новый QR`. Сканируй тот, что появится ниже.
6. **Запасной путь без камеры:** скопируй из окна строку `tg://login?token=…`, отправь её себе
   в «Избранное» на телефоне и тапни по ней, пока скрипт ждёт (важно: окно не должно быть закрыто —
   ссылка действует только пока скрипт ждёт подтверждения).

## Шаг 8. Настроить уведомления в Telegram от бота (5 мин)

Чтобы совпадения приходили сообщением, а не только в консоль.

1. В Telegram напиши **@BotFather** → `/newbot` → имя и username → получишь токен вида
   `1234567890:AAH...`.
2. Напиши своему новому боту любое сообщение (иначе он не сможет тебе писать).
3. Узнай свой `chat_id`: напиши **@userinfobot** → он покажет `Id: 123456789`.

```bash
# ключи бота
export TG_BOT_TOKEN=1234567890:AAH...      # Windows: set / $env:
export TG_NOTIFY_CHAT=123456789

# проверка: должно прийти сообщение в Telegram и текст в консоль
python monitor.py --test-notify --notify both
```

Внутри сообщения — ссылка «открыть сообщение ↗» прямо на найденный пост.

**Если приходит `уведомление боту не ушло: HTTP Error 401: Unauthorized`** — Telegram не принял
токен. Что проверить, по порядку:

1. `TG_BOT_TOKEN` скопирован **целиком** из @BotFather (Мой бот → API Token) — вид `1234567890:AAH...`.
   Частая причина: скопирована половина или остались кавычки/пробелы.
2. Токен — от **твоего** бота, и бот не удалён.
3. `TG_NOTIFY_CHAT` — свой числовой id (у @userinfobot) или `@канал`; и ты **нажал Start** у бота,
   иначе он не имеет права писать тебе первым.
4. Изменил `.env` → открой **новое** окно cmd (файл читается при запуске).

Проверка без запуска мониторинга (сразу скажет, что ответил Telegram):
```bat
start.bat --test-notify --notify bot
```
Вывод вида `[i] проверка токена: бот @my_radar_bot (id=123...)` — значит токен в порядке, дело не в нём.

**Что происходит при 401 в боевом режиме.** Уведомления ботом выключаются до конца прогона
(одна понятная строка вместо потока ошибок), а сами совпадения **не теряются**: они уходят
пересылкой, и их можно догнать позже, когда токен исправлен:
```bat
start.bat --resend-pending 50 --notify bot      догоняет до 50 неотправленных уведомлений
```
Сколько копится — видно при старте («в базе N неотправленных уведомлений») и в конце прогона.
Если уведомления ботом тебе не нужны вовсе — их роль выполняет сама пересылка,
запускай с `--notify console`.

## Шаг 9. Запустить в боевом режиме (2 мин)

Два способа, выбирай один.

**А. Постоянный процесс (ловит мгновенно):**
```bash
python monitor.py --notify bot --catchup 30 --heartbeat 15     # или: ./start.sh --notify bot
```
Молча висит и ловит новые сообщения. Останавливается по `Ctrl+C`; база и сессия остаются.
Для круглосуточной работы на своём компьютере удобнее «Б».

**Б. По расписанию раз в 10 минут (не держит процесс):**
* **macOS/Linux:** `crontab -e` и строка
```cron
*/10 * * * * cd /полный/путь/telegram-scraper && .venv/bin/python monitor.py --once --notify bot >> monitor.log 2>&1
```
* **Windows:** Планировщик задач → «Создать задачу» → триггер «Каждые 10 минут» →
  действие «Запустить программу»:
  * программа: `C:\Users\User\Desktop\telegram-scraper\.venv\Scripts\python.exe`
  * аргументы: `monitor.py --once --notify bot`
  * рабочая папка: `C:\Users\User\Desktop\telegram-scraper`
  * в свойствах задачи: «Выполнять вне зависимости от того, вошёл ли пользователь».
  Ключи подхватятся из `.env` автоматически (это встроено в скрипт).
  Если хочешь запускать через батник — добавь ему `--no-pause`, иначе задача будет «висеть» на паузе:
  `start.bat --once --notify bot --no-pause`.
  Важно: первый вход в аккаунт сделай вручную заранее — в фоне Telegram не даст ввести код.

`--once` читает только то, чего нет в базе, поэтому дублей не будет, а частые запуски
безопасны для аккаунта (запросов почти нет: сообщения приходят пушем).

## Окно свежести: чтобы старое не шло в уведомления

По умолчанию радар уведомляет только о сообщениях **не старше 24 часов** (`--max-age 24`).
Это защищает от двух ситуаций: свежая установка/новая база не вывалит пачку старых объявлений,
а после `--reset-db` не придёт всё заново. Всё, что старше окна, помечается просмотренным и молча
пропускается (в статистике видно как `too_old`).

```bat
start.bat --once --catchup 50                     окно по умолчанию: 24 часа
start.bat --once --max-age 6                      только за последние 6 часов
start.bat --once --max-age 48                     за двое суток
start.bat --once --max-age 0                      без ограничения (уведомлять и о старом)
```

Как это выглядит в выводе:
```
[i] catch-up @travelersminsk: прочитано 20, совпадений 3, старше 24 ч пропущено 12
```

Схема простая: **`seen`-таблица помнит всё, что уже разобрано** (поэтому повторно ничего не
приходит никогда), а `--max-age` дополнительно отсекает по возрасту то, что ты и так пропустил.
Пример «сейчас 11:00»: сообщения с 11:00 вчера до 11:00 сегодня — в работу, более старые — мимо.

## Как читать итоги прогона (пример)

```
[i] catch-up @travelersminsk: прочитано 50, совпадений 3, старше 24 ч пропущено 0
[i] catch-up @belgranica:     прочитано 50, совпадений 5, старше 24 ч пропущено 0
[i] catch-up @granica_es:     прочитано 30, совпадений 0, старше 24 ч пропущено 0
[i] catch-up @granica_bypl:   прочитано 30, совпадений 3, старше 24 ч пропущено 0
[i] итоги прогона: {'scanned': 37, 'matched': 11, 'saved': 11, 'duplicates': 123,
                    'text_duplicates': 4, 'cross_chat_duplicates': 4, 'forwarded': 11}
```

| Поле | Что значит |
|---|---|
| `прочитано 50` | в этом чате прочитан хвост из 50 сообщений (значение `catchup` из `sources.yaml`) — **свой для каждого чата** |
| `scanned: 37` | из 160 прочитанных сообщений 37 оказались новыми (остальные 123 — уже разобраны ранее) |
| `matched: 11` | сколько прошло правила |
| `saved: 11` | сколько легло в базу |
| `duplicates: 123` | уже виденные сообщения — это норма, а не ошибка: catchup читает хвост заново, а база помнит всё |
| `'hidden': 3` | столько объявлений пропущено: автор со скрытым профилем («hidden by user»), ему нельзя написать (см. раздел выше) |
| в пульсе `сообщений не было` | в чатах тихо (или ещё ночь) — это не поломка; проверь строку `последнее сообщение ЧЧ:ММ` |
| `cross_chat_duplicates: 4` | одно и то же объявление пришло из нескольких чатов → боту ушло один раз |
| пустое «название» у чата в отчёте | подписывается из `sources.yaml`; если названия нет и там — берётся из последней находки |
| `forwarded: 11` | ушло боту. `сегодня уже отправлено 1` — это `--test-forward` из прошлого раза (теперь такие проверки помечаются `test` и в счётчик не попадают) |

## Что показывается в командной строке

Просматриваются **все** сообщения из чатов (иначе радар не сможет решить, подходит ли сообщение),
а в консоль попадают **только совпадения** — то есть весь поток в окне не мелькает. В статистике
видно всю картину:

```
[i] catch-up @travelersminsk: прочитано 20, совпадений 12, старше 24 ч пропущено 0
[i] статистика: {'scanned': 80, 'matched': 38, 'saved': 21, 'duplicates': 0,
                 'text_duplicates': 8, 'cross_chat_duplicates': 9, 'filtered': 0, 'too_old': 0}
```

| Поле | Значение |
|---|---|
| `scanned` | сколько сообщений просмотрено |
| `matched` | сколько прошло правила |
| `saved` | сколько новых записей (остальное — дубли между чатами) |
| `text_duplicates` / `cross_chat_duplicates` | одно и то же объявление из нескольких чатов |
| `filtered` | отсеяно твоими фильтрами (`--category`, `--only-intent`, `--only-direction`) |
| `too_old` | старше окна `--max-age` |

**Про «счёт» в уведомлении** — это вес совпадения: сумма сработавших правил. Чем больше сигналов
(предмет + намерение + маршрут + детали), тем выше. Ориентир: 8–12 — слабое совпадение,
13–17 — типичное объявление, 18+ — очень явное. Если поток слишком шумный — подними `--min-score`.

## Как убрать попутчиков-людей (нужны только посылки и передачи)

Радар различает три категории: `parcel` — посылки/передачи/документы/груз, `ride` — попутчики
и пассажиры, `mixed` — водитель берёт и людей, и груз. Если пассажирские объявления не нужны:

```bat
start.bat --notify bot --category parcel,mixed      посылки; «люди + посылки» тоже показываем
start.bat --notify bot --category parcel            только чистая передача (без мест для людей)
start.bat --notify bot --category ride              наоборот, только попутчики
```

Проверить на конкретном тексте, что попадёт, а что нет:
```bat
python matcher.py --text "Еду 11:00 Брест-Тересполь, могу взять попутчиков, комфортное авто"
python matcher.py --text "Везу передачи и документы Минск-Варшава, есть места" --category parcel
```

Рекомендую держать `--category parcel,mixed`: чисто пассажирские посты исчезнут, а смешанные
(«есть 4 места и посылки») останутся — там часто есть кому передать груз.

Ориентир на реальном прогоне (11 находок за один проход): при `--category parcel,mixed` боту
ушло бы 3, при `--category parcel,mixed --only-intent request` — 1. Если хочешь меньше шума —
комбинируй оба флага, но держи в уме: чем строже фильтр, тем больше находок остаётся только
в базе (`hits.sqlite3`) и в `stats.txt`, а не в чате с ботом.

## Пересылка найденного боту @parcel_transfer_bot

Пересылает **твой аккаунт** (не копия — именно forward), получатель задаётся в `sources.yaml`:

```yaml
forward:
  to: "@parcel_transfer_bot"
  mode: forward            # forward — честная пересылка; copy — текст со ссылкой
  max_per_day: 180         # лимит отправок в сутки (0 — без лимита)
  fallback: link           # если в чате запрещена пересылка: link (текст+ссылка) или skip
```

**Что происходит, когда лимит на сегодня исчерпан.** Находка **не теряется**: она встаёт
в очередь и уходит боту в следующий прогон — добор идёт первым делом, сразу после того,
как лимит обнулится в **местную полночь** (по твоим часам, не по UTC). В логе видно:

```
[!] Дневной лимит пересылок (180) исчерпан. Находки не теряются: они встают в очередь...
[i] добор из очереди: ждёт 8, свободно отправок сегодня: 180
[i] добор: отправлено 8, не нашлось 0, ошибок 0, осталось в очереди ещё 0
```

Если радар запущен на несколько суток подряд (живой режим), **перезапускать его не нужно**: в
местную полночь лимит обнуляется сам, и очередь добирается на ходу — в логе это выглядит так:

```
[i] новый день (19.09): лимит пересылок обнулён, в очереди 6
[i] добор из очереди: ждёт 6, свободно отправок сегодня: 150
[i] добор: отправлено 6, не нашлось 0, ошибок 0, осталось в очереди ещё 0
```

**Один раз подготовь бота:** открой с этого же аккаунта чат с `@parcel_transfer_bot` и нажми
**Start**. Без этого аккаунт не сможет ему писать — Telegram не даёт начать диалог с ботом,
пока ты его не запустил. Если диалог уже активен — этот шаг пройден, переходи к проверке ниже.

**Проверка перед боевым запуском** (пересылает боту последнее сообщение из первого чата):

```bat
start.bat --test-forward
```

Возможные ответы:
```
[+] Пересылка работает: сообщение ушло боту как forward (видно источник).
[i] Пересылка в этом чате запрещена — ушёл текст со ссылкой (fallback).
[i] dry-run: отправка не выполнялась, путь проверен.
[!] Отправить не удалось — смотри причину выше.
```
Проверь в чате с ботом: должно прийти само сообщение из чата, а не твой текст.
Проверка **не съедает дневной лимит** и не попадает в статистику отправок (`mode=test`),
но само сообщение помечается пересланным — повторно боту оно не уйдёт, дубликатов не будет.

Если при входе в логе пишет `вошли как . (id=…)` — это не ошибка: у этого аккаунта
в профиле Telegram имя буквально «.». Поменять: Настройки → Изменить профиль → Имя.

Запуск:

```bat
start.bat --once --catchup 20                     пересылка включится из конфига
start.bat --notify bot --forward-to @parcel_transfer_bot      или явно в командной строке
start.bat --once --forward-dry-run                проверить без реальной отправки
```

Что важно знать:

| Ситуация | Что делает радар |
|---|---|
| Обычный чат | честная пересылка (forward) — видно, откуда пришло |
| В чате запрещено сохранение контента | `fallback: link` — уходит текст + ссылка на первоисточник |
| Уже пересылали это сообщение | повторно не уйдёт (запись в базе) |
| Достигнут `max_per_day` | лишнее встаёт в очередь и уходит в следующий прогон (с местной полуночи) — ничего не теряется |
| `PEER_FLOOD` при отправке | отправка останавливается, в логе причина; выжди 24–48 ч |

Пауза между отправками берётся из `--delay` (по умолчанию 2 с), FloodWait соблюдается.
Сколько ставить на практике. С десяти чатов поток в вечерний пик — **8–12 находок в час**
(видно по пульсу: `пришло 31, найдено 3` за 15 минут). За сутки это 120–200, поэтому:

| `max_per_day` | что будет |
|---|---|
| 100 | упирается уже к вечеру, часть находок приходит только на следующий день |
| 150 | хватает на спокойные сутки, в пиковые вечера очередь накапливается |
| **180** | рабочий компромисс (стоит в конфиге по умолчанию) |
| 200+ | выше не советую: 20–30 отправок в час — уже заметный для Telegram ритм |

Лимит ничего не теряет — лишнее идёт в очередь и добирается ночью, — поэтому если очередь
растёт изо дня в день (`в очереди N` в пульсе), поднимай шагом по 20 до 200.
Сколько сейчас ждёт отправки, видно в `stats.txt` (строка «сейчас в очереди») и в конце прогона
(`пересылка: отправлено за сегодня 148 (лимит 150), в очереди на добор 6`).

## Два аккаунта: больше чатов и два независимых лимита

Один аккаунт читает не бесконечно много: у Telegram есть суточные ограничения на чтение истории
и на пересылку. Второй аккаунт решает две задачи сразу:

* **больше чатов** — часть чатов следит первый аккаунт, часть второй (каждый «отвечает» за свои);
* **больше пересылок** — у каждого аккаунта **свой** дневной лимит; 120 + 60 = 180 отправок в сутки,
  и при этом ни один аккаунт не выходит за свой порог.

База и дедупликация **общие**: одно и то же объявление, попавшее в два чата, уйдёт боту только
один раз, каким бы аккаунтом его ни нашли.

### Что сделать (3 шага, один раз)

**Шаг 1. Войти вторым аккаунтом** (только он новый; первый уже настроен):

```bat
start.bat --login-qr --session second_session
```

Проще всего — по QR: телефон → Настройки → Устройства → Подключить устройство. Файл появится
рядом с `monitor.py`: `second_session.session`. Отдельный телефон/номер для него не нужен, но
аккаунт должен быть подписан на те чаты, которые ему достанутся.

**Шаг 2. Открыть `sources.yaml` и снять «#» в блоке `accounts`** (он уже там, в середине файла):

```yaml
accounts:
  main:
    session: monitor_session     # первый аккаунт — файл, который уже есть
    forward:
      to: "@parcel_transfer_bot"
      max_per_day: 120           # у каждого аккаунта свой лимит (сумма ~180)
  second:
    session: second_session      # второй аккаунт
    forward:
      to: "@parcel_transfer_bot"
      max_per_day: 60
```

**Шаг 3. Разделить чаты** — у источников внизу файла поставить, кто за какой следит:

```yaml
  - target: "@granica_BY_LT_PL"
    account: main                # за этот чат следит первый аккаунт
  - target: "@granica_polska"
    account: second              # за этот — второй
  - target: "@travelersminsk"    # без строки account — первый аккаунт (main)
    account: auto                # либо так: раскидать чаты по аккаунтам по кругу
```

Правило простое: `account: main` / `account: second` — вручную; `account: auto` — по кругу;
вообще без строки — первый аккаунт. Аккаунт, которому не досталось ни одного чата, просто
пропускается (в логе будет `у аккаунта «second» нет чатов в конфиге`).

### Проверить, что видит радар

```bat
start.bat --doctor
```

В блоке конфига появится:

```
      аккаунты:
PASS main: сессия monitor_session.session
      → лимит пересылок 120/сутки
WARN second: сессия second_session.session — файла нет, потребуется вход (start.bat --login-qr --session second_session)
      → лимит пересылок 60/сутки
```

`WARN про сессию` = аккаунт ещё не входил (это лечится шагом 1), всё остальное — уже готово.

### Как это выглядит при запуске

```bat
start.bat --once --catchup 20 --category parcel,mixed --max-age 24
```

```
[i] конфиг: …\sources.yaml (yaml), источников 10, аккаунтов 2 (main, second), лимит пересылок —/сутки, порядок обхода random
[i] аккаунтов в работе: 2
    • main: сессия monitor_session.session, чатов 6, лимит пересылок 120/сутки
    • second: сессия second_session.session, чатов 4, лимит пересылок 60/сутки
[+] [main] вошли как Твоё Имя (id=…)
[+] [second] вошли как Второй Аккаунт (id=…)
[i] [main] пересылка: отправлено за сегодня 7 (лимит 120)
[i] [second] пересылка: отправлено за сегодня 3 (лимит 60)
```

Пульс в живом режиме тоже подписывается аккаунтом (`[main] …`, `[second] …`), а в уведомлении и в
отчёте видно, чей аккаунт нашёл объявление.

**Полезно знать:**

* запустить только один аккаунт: `start.bat --account second` (для отладки и для проверок);
* лимит «сколько уже отправлено сегодня» у каждого аккаунта считается отдельно, очередь
  отложенных тоже раздельная: находка, пойманная вторым аккаунтом, ждёт добора именно вторым;
* **одну и ту же сессию нельзя запускать одновременно в двух местах** (ПК и сервер): Telegram
  отзовёт ключ, в логе будет `AuthKeyDuplicatedError`. Останавливай старую копию перед переездом;
* второй аккаунт — тоже живой человек: не создавай его ради обхода лимитов одного и того же
  поведения. Разумно: разные чаты у разных аккаунтов + умеренный ритм у обоих.


Строка вида `+CmQyl50rf-NlODFi` в отчёте — это приватный чат (в базе он лежит под ключом
`invite:CmQyl50rf-NlODFi`): у чатов без публичного имени читаемого имени нет, поэтому так.

Пример готового отчёта: `examples/stats-example.txt`.

## Первые сутки: поток уведомлений (важно)

В твоих чатах объявлений очень много (пример: 38 совпадений на 80 сообщений за один проход).
Если оставить как есть — уведомления будут идти часто. Что с этим делать:

```bat
start.bat --notify bot --only-intent request      только те, кто ИЩЕТ (передать/доехать)
start.bat --notify bot --only-intent offer        только те, кто ПРЕДЛАГАЕТ (везу/есть места)
start.bat --notify bot --only-direction PL->BY    только нужные направления (можно списком)
start.bat --notify bot --min-score 12             заметно строже (меньше находок, выше точность)
start.bat --export hits.csv                       накопленное — в CSV
start.bat --reset-db                              очистить базу и пересобрать заново
```

Категории в уведомлениях: `📦` посылка/передача, `🚗` попутчик/пассажир, `📦🚗` смешанное
(водитель берёт и людей, и груз). Направление вида `BY->PL` — из Беларуси в Польшу.

Одинаковые объявления из разных чатов приходят **одним** уведомлением (`--dedup-scope global`,
по умолчанию): водители обычно постят одно и то же в 3–4 чата. Если нужны все вхождения —
`--dedup-scope chat`.

## Шаг 10. Настроить под себя (первые сутки, по желанию)

1. Посмотри первые 20–30 находок: `python monitor.py --export hits.csv`.
2. Если **много мусора** — подними порог у шумного чата в `sources.yaml` (`min_score: 5` → `6`).
   Если **мало находок** — опусти на 1 (ниже 4 не советую).
3. Если видишь пропуски — добавь 5–10 реальных фраз в `tests/labeled_pos.txt`
   (и мусорные — в `tests/labeled_neg.txt`), прогони `python selftest_monitor.py`,
   правь веса в `RULES` в `matcher.py`. Это безопасный способ тюнинга: без аккаунта и без риска.
4. Хочешь добавить ещё чаты — впиши в `sources.yaml`:
```yaml
  - target: "@имя_чата"      # или ссылка https://t.me/... , или -100... для приватных
    profile: chat            # chat — чат объявлений, news — новостной канал с очередями
    min_score: 5
    catchup: 30
```

## Скрытые авторы: чьи объявления не берём

Некоторые объявления приходят **пересланными от людей со скрытым профилем**: в Telegram видно имя,
но по нажатию — «hidden by user», профиль не открывается. Такому человеку **нельзя написать**,
поэтому радар их пропускает: в базу и боту они не попадают.

Как это выглядит в логе при каждом запуске:

```
[i] авторы со скрытым профилем («hidden by user») пропускаются: написать им нельзя
    (оставить их: --keep-hidden или skip_hidden: false в конфиге)
```

Сколько таких отсеялось, видно в итогах прогона (`'hidden': 3`), в `stats.txt`
(`пропущено из-за скрытых авторов («hidden by user»): 3`) и в пульсе (`скрытых авторов 1`).
Хочешь посмотреть, что именно пропускается, — добавь `--explain`:

```bat
start.bat --once --catchup 50 --explain
[i] пропущено, автор скрыт: https://t.me/granica_BY_LT_PL/258667 — переслано от скрытого
    пользователя «Olga OlgaB_O»: профиль закрыт, написать автору нельзя
```

Настройка в `sources.yaml` (секция `defaults`):

```yaml
  skip_hidden: true        # true — пропускать таких авторов; false — брать всё
```

Разово можно переопределить флагом: `--keep-hidden` — не отсекать никого.

Что важно знать: фильтр срабатывает там, где **сам Telegram скрыл автора** — то есть у пересланных
сообщений без идентификатора отправителя (`from_id`) и у пересылок из скрытых источников. Если
человек написал объявление прямо в чате, его автор виден всегда — такие сообщения проходят как обычно.

## Пульс: как понять, что живой режим работает

Живой режим молчит, пока нет находок, — и это неотличимо от «завис». Пульс решает вопрос:
раз в N минут в консоль падает одна строка.

```bat
start.bat --notify console --category parcel,mixed --max-age 24 --heartbeat 15
```

```
[i] [14:55] жив, слушаю 10 источник(ов) · с прошлого пульса: пришло 37, найдено 3, повторов 20,
    мимо 4 · всего находок 12 · переслано сегодня 84/150 · последнее сообщение 14:51 @granica_polska
```

Что видно из строки: процесс на связи, **сколько сообщений реально пришло** за интервал (даже если
под правила они не подошли), сколько из них стало находками, сколько уже было (повторы — это норма),
сколько отсеялось (мимо), что с пересылкой и очередью, и **когда было последнее принятое сообщение**.
Последняя часть — самая полезная: если написано `сообщений не было`, значит радар на связи, просто
в чатах тихо; если же последнее сообщение было давно, а в чатах пишут — это повод проверить запуск.

Тихий ночной интервал выглядит так:

```
[i] [03:08] жив, слушаю 10 источник(ов) · с прошлого пульса сообщений не было · всего находок 48 ·
    переслано сегодня 100/100 · в очереди 4 · последнее сообщение 23:41 @belgranica
```

Первый пульс печатается сразу при старте, дальше — по таймеру. Выключить: `--heartbeat 0`
или `heartbeat: 0` в `sources.yaml`.

## Бот-панель: смотреть статистику из Telegram

Зачем: не открывать консоль на домашнем ПК, а в телефоне спросить у бота «работает ли радар
и живы ли мои аккаунты» и получить цифры. Бот при этом **не трогает** твои сессии: он читает
базу `hits.sqlite3`, которую ведёт радар (поэтому запуск панели не может отозвать ключ аккаунта).

### Что нужно (один раз)

1. Бот уже создан для уведомлений (шаг 8): `TG_BOT_TOKEN` в `.env`.
2. В `TG_NOTIFY_CHAT` должен быть **числовой id** (узнать — у @userinfobot), например `123456789`.
   С каналом вида `@my_channel` панель не работает: команды принимаются только в личке с ботом.
   Если в `.env` написано не число, панель откажется стартовать и объяснит, что поправить.

### Запуск вместе с радаром

```bat
start.bat --bot-panel --notify none --heartbeat 15
```

При старте бот пришлёт «📡 панель на связи», дальше — отвечаешь ему командами:

| Напиши боту | Что пришлёт |
|---|---|
| `/status` | режим (A/B), аптайм, сколько прочитано (всего и за час), находки и пересылки сегодня, очередь, ошибки за сутки |
| `/accounts` | по каждому аккаунту: «работает» или «молчит N мин», последний пульс, последнее событие, переслано/лимит, очередь, ошибки |
| `/stats 7` | статистика за 7 дней (тот же текст, что в `stats.txt`) |
| `/report` | `stats.txt` файлом — удобно, когда отчёт длинный |
| `/queue` | что висит в очереди на добор и с какого времени |
| `/last 10` | последние 10 находок со ссылками |
| `/usage` | память, процессор, аптайм, размер базы, нагрузка и вердикт «A подходит / рекомендую B» |
| `/errors 10` | последние ошибки с временем и аккаунтом |
| `/sources`, `/top`, `/limits`, `/mode`, `/ping`, `/why <id>`, `/export`, `/digest on` | остальное: список — `/help` |

### Как читать «работает» и «молчит»

Живость определяется **пульсом**, а не находками. Пульс — это строка в базе раз в
`--heartbeat` минут (с `--bot-panel` пульс включается сам: 15 минут, если он был выключен).

* `работает` — пульс был недавно;
* `молчит 34 мин ⚠️` — пульса нет дольше порога (`--alert-silent`, по умолчанию 30 минут).
  Чаще всего значит, что окно радара закрыли, процесс завис или сессию занял второй процесс;
* `остановлен` — радар завершился штатно (нажали Ctrl+C);
* `нет данных о пульсе (радар мог быть запущен без --heartbeat)` — радар работает без пульса,
 панель сказать о нём ничего не может. Это **не** «аккаунт сломан»: включи `--heartbeat 15`.

Тихий чат ночью — норма: находок может не быть часами, а аккаунт при этом жив.

### Алерты: бот напишет сам

* «⚠️ second молчит 34 мин (последний пульс 20:40)» — не чаще раза в час на аккаунт;
* «сессия сломана» (`AuthKeyDuplicatedError`, бан номера) — однократно, с командой для входа;
* FloodWait, «дневной лимит выбран», «очередь растёт вторые сутки»;
* утренний дайджест в 09:00 местного — включается `/digest on` (или `--digest on`).

### Панель отдельным процессом (радар на сервере, статус в телефоне)

```bat
start.bat --panel-only
```

Ключи аккаунта (`TG_API_ID`/`TG_API_HASH`) для этого режима **не нужны** — только
`TG_BOT_TOKEN` и `TG_NOTIFY_CHAT`. Панель читает ту же базу (она открывается в режиме WAL,
поэтому радар и панель не мешают друг другу) и помечает в `/status`, что данные из базы
и когда они обновлены.

### Проверить сессии вручную — только при остановленном радаре

```bat
start.bat --check-sessions
```

Команда делает настоящий вход по каждому `.session` и показывает, жив ли аккаунт. Если радар
сейчас работает (в базе свежий пульс), команда **откажется** выполняться: второй клиент на тот
же файл сессии — это `AuthKeyDuplicatedError` и вход заново. Сначала останови радар.

### Самопроверка панели (без сети и без бота)

```bat
python selftest_panel.py
```

Ожидаемый конец вывода: `ИТОГ: всё ок` (82 проверки). Тесты подменяют Bot API фейковым
транспортом, поэтому ни интернет, ни токен, ни аккаунт не нужны — и заодно проверяется,
что панель ни разу не создала Telethon-клиент.

## Расход: хватает ли схеме A ресурсов

«А не много ли жрёт постоянный слушатель?» — теперь вопрос с цифрами, а не на глаз. Радар сам
меряет память, процессор и нагрузку, а потом прямо говорит: `A подходит`, `A возможна, но следи`
или `рекомендую B (проходы по расписанию)`.

### Включать ничего не нужно

По умолчанию раз в 15 минут срез (память, процессор, аптайм, сколько прочитано, API-вызовы,
размер базы) ложится в `hits.sqlite3`, а раз в час — строкой в `metrics.csv` рядом с проектом.

```bat
start.bat --bot-panel --heartbeat 15            :: обычные сутки работы, метрики пишутся сами
start.bat --metrics-interval 5                  :: хочется подробнее (срезы раз в 5 минут)
start.bat --metrics-interval 0                  :: метрики не нужны вовсе
start.bat --metrics-csv out\metrics.csv         :: положить файл в свою папку
```

### Где смотреть

1. **В Telegram** — напиши боту `/usage` (нужна панель: `--bot-panel` или `--panel-only`).
2. **В консоли** — после прохода `--once` радар печатает `[i] расход: ...` и строку вердикта.
3. **В Excel** — открой `metrics.csv`: utf-8, разделитель `,`, за сутки 24–96 строк.

Вот как выглядит ответ `/usage` после суток работы:

```text
🧮 Расход и нагрузка · режим A (слушатель) · аптайм 1 дн 2 ч 40 мин

Память: 62 МБ (пик 78) · процессор: 1.5 % (среднее за сутки)
База: 11.2 МБ (WAL 0.4) · диск под проект: 14 МБ
Сообщений: 41 208 всего · за час 208 · пик 12/мин (20:10)
API-вызовов: 1 902 · FloodWait: 0 · Ошибки: 0
Находок: 61 · переслано сегодня 44/180 (main 28/120, second 16/60) · в очереди 3

Вердикт: A подходит: ресурсов мало (RSS 62 МБ ≤ 150, CPU 1.5 % ≤ 5)
Сутки: 2026-09-25 → RSS 62 МБ, CPU 1.5 %, 41 208 сообщений, 96 срезов
```

### Как читать вердикт

| Что написано | Что это значит |
|---|---|
| `A подходит: ресурсов мало` | RSS ≤ 150 МБ и CPU ≤ 5 %, FloodWait и ошибок сессии нет — оставляй слушателя |
| `A возможна, но следи` | 150–250 МБ или CPU до 15 %: работает, но впритык к лимитам лёгкого контейнера |
| `рекомендую B (проходы по расписанию)` | больше 250 МБ, больше 15 % CPU, ≥ 3 FloodWait за сутки или сломанная сессия |
| `н/д: нет данных о ресурсах` | ни `psutil`, ни `/proc`: смотреть на FloodWait и ошибки (обычно Windows без psutil) |

Пороги подобраны под Cloudflare Containers lite (256 МБ) и лежат в начале `metrics.py`
(`RSS_OK_MB`, `RSS_WARN_MB`, `CPU_OK_PERCENT`, `CPU_WARN_PERCENT`, `FLOOD_WARN_PER_DAY`) —
под своё железо правятся в одном месте.

### Когда переходить на схему B

Если вердикт `рекомендую B` (или среда просто не даёт держать процесс живым) — ничего
переписывать не нужно: это тот же радар с флагом `--once` по расписанию.

```bat
start.bat --once --catchup 0 --notify bot --forward-max-per-day 180
```

В Планировщике задач Windows (или в cron) — раз в 10 минут. Задержка до 10 минут, зато процесс
не висит постоянно. Подробно про расписание и хостинг — `HOSTING.md`.

### Про psutil (не обязательно)

С `psutil` память и процессор измеряются точнее и работают на любой системе:

```bat
pip install psutil
```

Без него радар **не падает и не врёт**: на Linux и Android цифры берутся из `/proc`, а на
Windows без psutil часть полей показывается как `н/д`, и `/usage` честно об этом пишет. В
`requirements.txt` строка закомментирована — ставь только если хочется.

### Самопроверка метрик (без сети, без аккаунта и без psutil)

```bat
python selftest_metrics.py
```

Должно быть `ИТОГ: всё ок` и 65 строк `PASS`: срез из подставленных значений, средний CPU,
вердикт на граничных 150/250 МБ и 5/15 %, формат `metrics.csv`, работа без psutil и ретеншн
(строки старше 31 дня удаляются, свежие остаются).

## Форум-чаты и темы (необязательно)

Если чат — форум (внутри много тем), по умолчанию радар читает **все** темы: обычная ссылка
на чат это покрывает, ничего настраивать не нужно.

Нужно следить только за конкретными темами — сначала посмотри их список с id:

```bat
start.bat --list-topics
```

```
@some_forum («Посылки/передачи») — тем найдено 2
      id темы  сообщений  название
          502          3  Попутчики
          501          2  Посылки Минск-Варшава

  чтобы читать только нужные темы, добавь в sources.yaml:
    - target: "@some_forum"
      topics: [502]
```

Потом впиши выбранные id в `sources.yaml`:

```yaml
  - target: "@some_forum"
    profile: chat
    min_score: 4
    catchup: 50
    topics: [502]          # читать только эти темы; id из --list-topics
```

Как это работает: при старте хвост читается **по каждой выбранной теме** отдельно, в живом режиме
сообщения из других тем отбрасываются (в пульсе видно `не в наших темах N`). В уведомлении
и в пересланном сообщении тема подписывается — `Граница BY-PL-LT · тема «Посылки»`.

Поиск тем идёт по последним сообщениям чата (в этой версии Telethon нет отдельного метода),
поэтому в редких случаях тему видно не сразу — увеличить окно поиска: `--topics-depth 1000`.

## Почему радар считает «не по тем» настройкам

Все настройки читаются из конфига **один раз при запуске** — правка `sources.yaml` в работающем
окне ни на что не влияет до перезапуска (`Ctrl+C`, потом снова `start.bat ...`).

**Приоритет настроек пересылки:** флаг в командной строке → `sources.yaml` → встроенное значение.
То есть без флагов берётся ровно то, что в файле; `--forward-max-per-day 200` перекрывает файл
только для этого запуска. Две строки в логе должны сходиться:

```
[i] конфиг: … sources.yaml (yaml), источников 10, лимит пересылок 180/сутки
[i] пересылка включена: @parcel_transfer_bot … лимит 180/сутки
```

Чтобы не гадать, какой файл реально прочитан, при каждом запуске печатается строка:

```
[i] конфиг: C:\Users\User\Desktop\telegram-scraper\sources.yaml (yaml), источников 10,
    лимит пересылок 150/сутки, порядок обхода random
```

Сверь этот путь с тем файлом, который правишь. Три частые причины расхождений:

1. **Архив распакован «в себя»** — Windows создаёт папку с тем же именем внутри рабочей:
   `Desktop\telegram-scraper\telegram-scraper\`. Тогда правки уходят в копию, а запускается
   версия из корня (или наоборот). Проверка: `start.bat --doctor` — при вложенной копии он
   напишет `WARN рядом лежит ещё одна копия проекта: …`. Лишнюю папку можно удалить.
2. **Расходятся `sources.yaml` и `sources.json`.** Читается YAML (если установлен pyyaml),
   а JSON лежит рядом и может содержать старые значения. Если файлы разошлись, при запуске
   появится `[!] sources.json в этой папке не совпадает с sources.yaml: лимит пересылок …`.
   Проще всего держать их одинаковыми или удалить ненужный.
3. **Осталось работать старое окно.** Строка `лимит N/сутки` при старте берётся из конфига,
   а строка `сегодня уже отправлено M` — из базы: если запустить второе окно с той же сессией,
   работать будут оба, и лимит окажется «общим» (а Telegram может начать ругаться на две сессии —
   так что лучше одно окно).

Полный список того, что радар видит прямо сейчас:

```bat
start.bat --doctor
```

## Если живой режим молчит

Порядок проверки, когда находок нет долго:

1. Посмотри пульс: `с прошлого пульса: пришло N` и `последнее сообщение ЧЧ:ММ @чат`.
   Есть приход и есть находки — всё работает, просто тихо.
2. Если в чатах явно пишут, а в пульсе `сообщений не было` или `последнее сообщение` — старая дата,
   запусти разовый проход и сравни: `start.bat --once --catchup 50 --category parcel,mixed`.
   Разовый проход читает хвост заново — если он находки видит, а живой режим нет, обнови архив
   (в версиях до 19.09 был баг: события живого режима не сопоставлялись с чатами из конфига,
   потому что Telegram присылает id каналов в «маркированном» виде `-100…`, а сущность чата
   отдаёт положительный id).
3. Строка `не сопоставлено сообщений N` в пульсе означает, что приходят сообщения из чата,
   которого нет в конфиге, — добавь его в `sources.yaml`.

## Порядок обхода чатов (случайный старт)

Каждый запуск радар проходит чаты **в случайном порядке** — в логе это видно сразу:

```
[i] порядок обхода случайный: начинаем с @granica_polska (отключить: --order config)
```

Зачем: чаты неравнозначны, а дневной лимит пересылок конечен. При фиксированном порядке чаты
из конца списка систематически получали бы «остатки» лимита или ничего — особенно на живом
прогоне, когда сообщения приходят в течение дня. Случайный старт размазывает лимит ровно по всем.

Нужен предсказуемый порядок (например, чтобы первым всегда шёл приоритетный приватный чат) —
поставь `order: config` в `sources.yaml` (секция `defaults`) или запусти разово:

```bat
start.bat --once --order config --catchup 20
```

### Приватные чаты по ссылке-приглашению

Если аккаунт ещё не в чате, обычная ссылка не читается. Два варианта:

```bat
start.bat --auto-join --once --catchup 20    подпишется по ссылкам из конфига и сразу прочитает
```

* `--auto-join` действует **только** на ссылки вида `t.me/+…` и `t.me/joinchat/…`;
  по username он никого никуда не добавляет — молча пропускает.
* Если аккаунт уже в чате, `--auto-join` ничего не делает (лишних вступлений не будет).
* Вступать много и сразу не стоит: 1–2 чата в час — спокойный ритм (за это Telegram ограничивает).
* Ключ приватного чата в статистике и в базе: `invite:<hash>`, на экране — `+<hash>`.

## Как добавить другие каналы и чаты

**Способ 1 — через файл конфигурации (основной).** Открой `sources.yaml` Блокнотом и добавь блок:

```yaml
  - target: "@имя_чата"        # или https://t.me/имя, или https://t.me/+hash (приватный), или -1001234567890
    title: "Как показывать в отчёте"   # необязательно
    profile: chat              # chat — чат объявлений; news — новостной канал (очереди, правила въезда)
    min_score: 5               # порог: 4 мягко, 6 строго
    catchup: 30                # сколько последних сообщений прочитать при старте
```

Файл `sources.json` — та же структура, если YAML не читается. Правь **любой один** из двух:
сначала читается `sources.yaml`, при его отсутствии — `sources.json`.

**Способ 2 — быстрая проверка без правки конфига:**
```bat
start.bat --once --channels @новый_чат --catchup 5
```

**Важно про подписки.** Telegram даёт читать только те чаты, где состоит **твой** аккаунт.
Поэтому для нового источника: подпишись на него тем же аккаунтом, что вошёл в радар.
Каналы с публичным username читаются и без вступления, но для групп и полной истории — нужно быть
участником. Массово вступать в десятки чатов в день не надо: это то самое действие, за которое
Telegram ограничивает аккаунт (по 1–2 в час спокойно).

**Если чат доступен только по ссылке-приглашению** — вставь её как `target: "https://t.me/+hash"`
и запусти один раз `start.bat --auto-join --once --catchup 20`: радар вступит в чат сам.
Если ты уже участник, `--auto-join` не нужен — ссылка читается сразу.

**Как узнать id приватного чата** (если нет username): перешли любое сообщение из него боту
`@userinfobot` — он покажет `Id: -100…`. Либо в самом Telegram: ссылка вида `t.me/c/1234567890/5`
означает чат с id `-1001234567890`.

**Проверка, что новый источник виден:**
```bat
start.bat --doctor
```
В списке источников появится новая строка. Если чат не разрешается (`не смог разрешить @…`),
значит аккаунт не подписан, или в username опечатка, или чат приватный и нужен id.

**Советы по настройке нового источника:**
| Что за чат | profile | min_score | catchup |
|---|---|---|---|
| Чат объявлений (передачи, попутчики) | `chat` | 4–5 | 30–50 |
| Новостной канал про границу | `news` | 6 | 20–30 |
| Очень шумный большой чат | `chat` | 6 | 20 |
| Маленький тихий чат | `chat` | 4 | 50–100 |

История нового чата **не подтягивается автоматически** задним числом: радар начнёт читать его
с момента добавления (плюс `catchup` последних сообщений). Нужен архив за прошлые месяцы —
это отдельная задача: `python scraper.py --mode history --channels @чат --since 2026-06-01`.

## Шаг 11. Что означает ошибка (шпаргалка)

| Сообщение | Причина | Что делать |
|---|---|---|
| `Синтаксическая ошибка в имени файла, имени папки или метке тома` | в **cmd** вставлена команда из **PowerShell** (`$env:...`) | в cmd пиши `set TG_API_ID=1234567`, а `$env:` — только в PowerShell; не смешивай |
| `Нужны TG_API_ID и TG_API_HASH` / «не задан» | переменные не заданы в этом окне | впиши их в `.env` (Шаг 4) — тогда один раз и навсегда |
| `Для YAML-конфига нужен pyyaml` | не выполнена установка зависимостей | **уже исправлено**: скрипт сам переходит на `sources.json`; либо `python -m pip install -r requirements.txt` |
| `pip` не является внутренней или внешней командой | pip не в PATH | используй `python -m pip install -r requirements.txt` |
| Кракозябры в надписях `[i] ╨б╤В╨░╨▓╨╗╤О...` | консоль в старой кодировке | косметика, уже исправлено: в `start.bat` добавлен `chcp 65001` и англоязычные служебные надписи; вывод самого Python — UTF-8 и читался нормально |
| Задача в Планировщике «висит» и не завершается | батник ждёт нажатия клавиши (`pause`) | добавь `--no-pause` или запускай `python.exe` напрямую, без батника |
| ключ «обрезан» (в `--doctor` — FAIL) | скопирована не вся строка из my.telegram.org | перекопируй полностью: `api_hash` — 32 символа |
| `Cannot find any entity corresponding to ...` | аккаунт не подписан на чат / опечатка в username | подпишись, либо укажи `-100…` id или ссылку `https://t.me/...` |
| `The code is invalid` | код введён не тот или просрочен | запроси новый (придёт в приложение) |
| `SessionPasswordNeededError` | включён 2FA-пароль | введи облачный пароль; см. раздел «Если Telegram пишет…» ниже |
| `PasswordHashInvalidError` | облачный пароль введён неверно | проверь раскладку/Caps Lock; если забыт — сброс в Telegram (см. ниже), не перебирай |
| `AttributeError: 'datetime.datetime' object has no attribute 'total_seconds'` | баг в старой версии `login_qr.py` | **исправлено** — обнови `login_qr.py` из архива |
| `400 AUTH_TOKEN_EXPIRED` | QR-код живёт 30–60 секунд — не успел отсканировать или подтвердить | ничего не делай: скрипт сам выдаст новый QR, просто сканируй следующий (см. «Как успеть отсканировать QR») |
| `The code is invalid` / `PhoneCodeInvalidError` | опечатка или код устарел (каждый запрос обнуляет предыдущий) | запроси новый **один** раз; если снова не приходит — `start.bat --login-qr` |
| `FloodWaitError: N seconds (caused by SendCodeRequest)` | слишком много запросов кода | подожди N секунд (иногда 10–30 минут) и войди по QR |
| `PHONE_NUMBER_BANNED` | номер заблокирован Telegram для API-входа | используй другой номер или войди по QR с аккаунта, который уже работает |
| `FloodWaitError: ... N seconds` | Telegram притормозил запросы | ничего не делай, скрипт сам выждет N секунд и продолжит |
| `PEER_FLOOD` | ограничение аккаунта (бывает у новых/«спамных») | останови запуски на сутки, потом уменьши `catchup` |
| в логе `лимит N/сутки`, хотя в файле другое число | либо конфиг не перечитан (правки видны только после перезапуска), либо запускается другая копия файла | сверь путь из строки `[i] конфиг: …` и запусти `--doctor`; в версиях до 21.09 флаги пересылки имели собственные значения по умолчанию и молча перекрывали конфиг — обнови архив |
| `Server closed the connection` + `Security error ... wrong session ID` | обрыв связи и переподключение: Telegram прислал ответ на старом соединении. Само по себе не опасно — радар продолжает работу, сессия цела | если сыплется постоянно: закрой второе окно с тем же `monitor.session`, не запускай сессию с двух IP (VPN/прокси) и проверь связь |
| `лимит обнулится в 00:00` в пульсе | на сегодня всё отправлено, остальное в очереди | нормально; в полночь добор пойдёт сам, перезапуск не нужен |
| `ModuleNotFoundError: telethon` | активировано не то окружение | запускай через `start.bat` (он сам берёт `.venv`) или `pip install -r requirements.txt` |
| Совпадений 0 и в новых сообщениях тоже | строгий порог / профиль `news` на чате объявлений | проверь: `python matcher.py --text "<текст сообщения>" --explain`, затем уменьши `min_score` |
| Находки есть, но уведомлений нет, в статистике `too_old` | сообщения старше `--max-age` (по умолчанию 24 ч) | это нормально; для старых запусти `--max-age 0` |
| `не смог разрешить @чат` | аккаунт не подписан / опечатка / приватный чат | подпишись или укажи `-100…` id (см. «Как добавить другие каналы») |
