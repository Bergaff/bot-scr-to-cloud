# Полный список команд радара

Все команды запускаются через `start.bat` (Windows) или `./start.sh` (mac/Linux) — они сами
подхватывают ключи из `.env`, ставят зависимости при первом запуске и передают флаги в `monitor.py`.
Прямой запуск тоже работает: `python monitor.py --once --catchup 20`.

Общий вид: `start.bat [режим] [что фильтровать] [куда уведомлять] [служебное]`

Ниже — все флаги, которые реально есть в коде, сгруппированные по смыслу.
★ — добавлено в последних версиях.

---

## 1. Режим работы (что именно делаем)

| Команда | Что делает |
|---|---|
| `start.bat` (без флагов) | живой режим: уведомления в консоль и `hits.log`, читает хвост 30 сообщений |
| `--once` | **разовый проход**: прочитать хвост по всем чатам, отправить найденное и выйти |
| `--catchup N` | сколько последних сообщений читать в каждом чате при старте (перекрывает `catchup` из конфига); `0` — не читать историю |
| `--channels @chat1,@chat2` | добавить чаты на этот запуск, не правя `sources.yaml` (чаты из файла тоже читаются) |
| `--order random\|config` ★ | порядок обхода чатов: `random` (по умолчанию) — каждый запуск со случайного чата, `config` — как в файле |
| `--heartbeat N` ★ | в живом режиме печатать пульс раз в N минут (`0` — выключить); показывает, что радар жив |
| `--delay N` | пауза между запросами к Telegram, сек (по умолчанию 2) |
| `--max-age N` | не уведомлять о сообщениях старше N часов (по умолчанию 24; `0` — без ограничения) |
| `--include-own` | не пропускать свои собственные сообщения (по умолчанию пропускаются) |

```bat
start.bat --once --catchup 20                     разовый проход, хвост 20 сообщений
start.bat --notify none --heartbeat 15            живой режим с пульсом каждые 15 минут
start.bat --once --catchup 20 --order config      строгий порядок чатов из конфига
```

## 2. Что считается находкой (фильтры и категории)

| Команда | Что делает |
|---|---|
| `--category parcel,mixed` | категории: `parcel` (посылки/передачи), `mixed` (посылки+попутчики), `ride` (только люди) |
| `--only-intent offer,request` | только предложения (`offer`) или только просьбы (`request`) |
| `--only-direction BY->PL,PL->BY` | только нужные направления (`?->PL` — любое «в сторону Польши») |
| `--min-score N` | порог срабатывания правил (по умолчанию из конфига, обычно 4–5; меньше — больше шума) |
| `--profile chat\|news` | `chat` — чат объявлений, `news` — новостной канал (гасит посты про очереди) |
| `--keep-hidden` ★ | **не** отсекать объявления от авторов со скрытым профилем («hidden by user»). По умолчанию такие пропускаются: профиль закрыт, написать автору нельзя |
| `--dedup-window N` | окно в часах, в котором одинаковые тексты считаются дублем (по умолчанию 24; `0` — выключить) |
| `--dedup-scope global\|chat` | `global` — дубли ловятся между чатами (по умолчанию), `chat` — только внутри одного чата |
| `--explain` | показывать, какие правила сработали, и почему сообщение пропущено (в т.ч. «автор скрыт») |

```bat
start.bat --once --catchup 20 --category parcel,mixed --max-age 24
start.bat --once --catchup 50 --only-intent request --only-direction PL->BY
start.bat --once --catchup 50 --explain            посмотреть, что и почему отсеялось
```

## 3. Уведомления

| Команда | Что делает |
|---|---|
| `--notify console` | уведомления в консоль (по умолчанию, если флаг не указан вообще) |
| `--notify file` | писать в файл |
| `--notify bot` | присылать сообщением от бота в Telegram (нужны `TG_BOT_TOKEN` и `TG_NOTIFY_CHAT`) |
| `--notify both` | и в консоль, и в файл |
| `--notify none` | не уведомлять (только пересылка и база) |
| `--notify-file hits.log` | имя файла для `--notify file\|both` |
| `--test-notify` | отправить одно тестовое уведомление и выйти; при `--notify bot` проверяет и токен (спросит у Telegram через `getMe`) |
| `--resend-pending N` ★ | догнать уведомления, которые не ушли раньше (после сбоя бота/401), по умолчанию до 50 штук |

```bat
start.bat --test-notify --notify bot              проверить, что бот настроен верно
start.bat --resend-pending 50 --notify bot        отправить накопившиеся уведомления
```

## 4. Пересылка найденного (forward боту)

| Команда | Что делает |
|---|---|
| *(настройки в `sources.yaml`, секция `forward`)* | `to`, `mode`, `max_per_day`, `fallback` — берутся из файла |
| `--forward-to @parcel_transfer_bot` | кому пересылать (перекрывает конфиг на этот запуск) |
| `--forward-mode forward\|copy` | `forward` — честная пересылка (видно источник), `copy` — текст со ссылкой |
| `--forward-max-per-day N` | лимит отправок в сутки (`0` — без лимита). Что не влезло — в очередь, уйдёт в следующий прогон |
| `--forward-fallback link\|skip` | если в чате запрещена пересылка: `link` — отправить текст со ссылкой, `skip` — пропустить |
| `--test-forward` | проверка: переслать последнее сообщение из первого чата боту и выйти (лимит не тратится, в статистике помечается `test`) |
| `--forward-dry-run` | всё то же, но без реальной отправки (в базу пишется `dry-run`) |

Приоритет: **флаг → `sources.yaml` → встроенное значение** (`forward`/`100`/`link`).

```bat
start.bat --test-forward                          проверить пересылку
start.bat --forward-max-per-day 200               разово поднять лимит до 200
```

### Несколько аккаунтов

| Команда / настройка | Что делает |
|---|---|
| секция `accounts` в `sources.yaml` | список аккаунтов: `session`, свой `forward` (получатель, лимит), `proxy`; без секции — один аккаунт `main` |
| `account: main\|second` у источника | какой аккаунт следит за чатом (без строки — первый; `auto` — раскидать по кругу) |
| `--account second` | запустить только этот аккаунт из конфига (остальные не поднимаются) |
| `enabled: false` у аккаунта | временно выключить аккаунт, не удаляя настройки |

```bat
start.bat --login-qr --session second_session     один раз войти вторым аккаунтом
start.bat --doctor                                проверить: сессии, лимиты, у кого сколько чатов
start.bat --account second --once --catchup 10    прогон только вторым аккаунтом
```

* у каждого аккаунта **свой** дневной лимит отправок и своя очередь отложенных; база и дедупликация — общие;
* флаги `--forward-to/--forward-max-per-day/...` перекрывают **первый** аккаунт; у остальных берутся настройки из `accounts`;
* в логе, пульсе, уведомлении и статистике появляется имя аккаунта (раздел «ПО АККАУНТАМ»);
* один `.session` — один запущенный процесс: вторая копия на том же файле даёт `AuthKeyDuplicatedError`.

## 5. Статистика и отчёты

| Команда | Что делает |
|---|---|
| `--show-stats` (`--stats-only`) | показать статистику и выйти (по каждому чату: прочитано / найдено / новых / переслано / фильтр / старше) |
| `--stats-days N` | сколько дней показывать в разбивке по дням (по умолчанию 7) |
| `--stats-file stats.txt` | файл статистики, обновляется после каждого запуска (пусто — не писать) |
| `--export hits.txt` | выгрузить найденное в TXT (открывается в Блокноте) и выйти |
| `--export hits.csv` | то же в CSV (для Excel) — формат определяется расширением |
| `--export-hours N` | для TXT: только совпадения за последние N часов (`0` — все) |
| `--reset-db` | удалить базу `hits.sqlite3` и выйти (находки соберутся заново в пределах `--max-age`) |

```bat
start.bat --show-stats --stats-days 30
start.bat --export hits.txt --export-hours 24
```

## 6. Чаты, подписки, темы

| Команда | Что делает |
|---|---|
| `--config sources.yaml` | какой файл конфига читать |
| `--auto-join` | вступать в чаты по ссылкам-приглашениям (`t.me/+...`), если аккаунт ещё не участник; по username никого не добавляет |
| `--list-topics` ★ | показать темы форум-чатов с их id и числом сообщений, потом выйти |
| `--topics-depth N` ★ | сколько последних сообщений просматривать при поиске тем (по умолчанию 300) |

Выбранные темы прописываются в `sources.yaml` у источника: `topics: [502]` — радар будет читать
только их (в уведомлении и пересылке тема подписывается).

```bat
start.bat --auto-join --once --catchup 20         подписаться по ссылкам и прочитать
start.bat --list-topics                           посмотреть темы с id
```

## 7. Диагностика и служебное

**Что за `api_id` и `api_hash`.** Это ключи ПРИЛОЖЕНИЯ, а не пароль от аккаунта: по ним
Telethon (и Pyrogram) говорят Telegram, какое приложение стучится в API. Создаются бесплатно
и один раз на **https://my.telegram.org/auth?to=apps**: войти номером телефона, название
приложения — **любое**, сохранить `App api_id` (число) и `App api_hash` (32 символа).
Приложение регистрируй на свой аккаунт: «чужие» готовые ключи из интернета делят одно
приложение на всех, и аккаунт с них слетает заметно чаще. `api_hash` не публикуй: если
засветился — удали приложение и создай новое.

| Команда | Что делает |
|---|---|
| `--login` | **мастер авторизации**: спросит `api_id`/`api_hash` (и покажет, где их взять), создаст и заполнит `.env`, войдёт по QR, определит `chat_id` бота |
| `--login --keys-only` | только ключи и `.env`, без входа (так готовят ключи для облака) |
| `--login --no-bot` | ключи и вход, без настройки бота |
| `--login --no-save` | ключи живут только в этом окне, `.env` не трогаем |
| `--login --session second_session` | мастер для второго аккаунта |
| `--doctor` | проверка окружения: Python, библиотеки, ключи, `.env`, путь к конфигу, список источников, лимит пересылки, наличие сессии. Работает офлайн |
| `--login-qr` | вход в Telegram по QR-коду (без SMS и кода) |
| `--login-qr --ascii-qr` | то же, но QR рисуется символами `##` (если код «рябит» в консоли) |
| `--db hits.sqlite3` | путь к базе данных |
| `--session monitor_session` | имя файла сессии Telegram |
| `--proxy socks5://…` | работать через прокси |
| `--api-id`, `--api-hash` | ключи Telegram на один запуск (обычно берутся из `.env`) |
| `--no-pause` | не ждать нажатия клавиши в конце (для Планировщика задач) |
| `--help` | краткая справка по флагам |

```bat
start.bat --login                                 первый запуск целиком: ключи -> .env -> QR -> бот
start.bat --doctor                                что радар видит прямо сейчас
start.bat --login-qr                              войти по QR (если ключи уже вписаны, а сессия слетела)
```

## 8. Бот-панель: статус и статистика из Telegram ★

Бот перестаёт быть только «громкоговорителем» и становится пультом: в личке видно, работает ли
радар, **живы ли аккаунты**, сколько найдено и переслано, что висит в очереди и какие были ошибки.
Нужны `TG_BOT_TOKEN` и **числовой** `TG_NOTIFY_CHAT` (свой id узнай у @userinfobot). Команды
принимаются только от владельца: чужие сообщения молча игнорируются и пишутся в журнал ошибок.

| Флаг | Что делает |
|---|---|
| `--bot-panel` | панель вместе с радаром: отдельная задача в том же окне, long polling Bot API |
| `--panel-only` | только панель, без радара и **без Telethon**: читает `hits.sqlite3` и отвечает на команды. Нужна, когда радар крутится на сервере/в контейнере, а статус хочется видеть в телефоне |
| `--alert-silent N` | через сколько минут без пульса слать алерт «аккаунт молчит» (по умолчанию 30; `0` — не слать) |
| `--digest on\|off` | утренний дайджест в 09:00 местного времени (то же, что `/digest` у бота) |
| `--check-sessions` | живая проверка сессий (`get_me` по каждому аккаунту). **Только когда радар остановлен**: второй клиент на тот же `.session` — это `AuthKeyDuplicatedError` и вход заново. При живом пульсе команда отказывается работать и объясняет почему |
| `--mode A\|B` | какая схема в отчётах панели: `A` — постоянный слушатель, `B` — проходы по расписанию (по умолчанию `A`, а с `--once` — `B`) |

Команды бота (писать в личке боту):

| Команда | Ответ |
|---|---|
| `/help` | список команд, по строке на команду |
| `/status` | общий статус: режим (A/B), аптайм, аккаунты, прочитано всего и за час, находки и пересылки сегодня, очередь, ошибки за сутки |
| `/accounts` | подробно по каждому аккаунту: «работает» или «молчит N мин», последний пульс, последнее событие, переслано/лимит, очередь, ошибки, FloodWait |
| `/stats [N]` | статистика за N дней (по умолчанию 7) — тот же текст, что `stats.txt`, обрезанный до лимита Telegram |
| `/report` | прислать `stats.txt` файлом (документом) |
| `/queue` | очередь отложенных пересылок: сколько, по аккаунтам, что самое старое, 5 примеров со ссылками |
| `/last [N]` | последние N находок (по умолчанию 5): время, чат, направление, ссылка |
| `/sources` | по каждому чату: прочитано, совпало, найдено за сутки, последняя находка, ошибки |
| `/errors [N]` | последние N ошибок (по умолчанию 5) с временем и аккаунтом |
| `/usage` | расход ресурсов: память (и пик), процессор, аптайм, размер базы, сообщения, API-вызовы, FloodWait и **вердикт «A подходит / рекомендую B»** |
| `/ping` | `pong · 0.4 с` — проверка связи с Bot API |
| `/mode` | какой режим сейчас, с какого времени и что советует метрика |
| `/digest on\|off` | утренний дайджест (итоги суток в 09:00 местного) |
| `/export [N]` | прислать `stats.csv` документом (+ находки за 24 ч, если они есть) |
| `/top` | топ чатов за сутки по находкам |
| `/limits` | лимиты пересылок и остаток по каждому аккаунту |
| `/why <id\|ссылка>` | почему сообщение взяли: счёт, категория, направление, сработавшие слова |

Алерты (бот пишет сам, с защитой от повторов):

| Алерт | Условие | Как часто |
|---|---|---|
| «аккаунт молчит» | нет пульса дольше `--alert-silent` | не чаще раза в час на аккаунт |
| «сессия сломана» | `AuthKeyDuplicatedError`, `PhoneNumberBannedError`, отозванная сессия | однократно |
| «FloodWait» | Telegram ограничил аккаунт | однократно на событие |
| «лимит исчерпан» | дневной лимит пересылок выбран, а находки идут | раз в сутки на аккаунт |
| «очередь растёт» | больше 50 позиций и не уменьшается вторые сутки | раз в сутки |
| утренний дайджест | 09:00 местного, если `/digest on` | раз в сутки |

```bat
start.bat --bot-panel --notify none --heartbeat 15     радар + панель в одном окне
start.bat --panel-only                                 панель отдельно (радар крутится своим ходом)
start.bat --check-sessions                             проверить сессии, когда радар остановлен
start.bat --bot-panel --alert-silent 45 --digest on    алерт о молчании через 45 мин + дайджест
```

**Как панель понимает, жив ли аккаунт.** По пульсу: `--heartbeat` раз в N минут пишет строку в
базу (`heartbeats`, `kind='pulse'`). С `--bot-panel` пульс включается сам (15 минут), если он был
выключен. Молчание = нет пульса, а **не** нет находок: тихий чат ночью — это норма, а не поломка.
Если пульса нет вовсе, панель честно пишет «нет данных о пульсе (радар мог быть запущен без
--heartbeat)», а не «аккаунт сломан».

**Чего панель не делает.** Не открывает Telethon-клиенты и не трогает файлы `.session` — иначе
Telegram отозвал бы ключ (`AuthKeyDuplicatedError`). Статусы берутся из базы: радар пишет
`heartbeats`/`errors`/`metrics`, панель читает их из того же `hits.sqlite3` (база открывается в
режиме WAL, поэтому два процесса не мешают друг другу). Живая проверка сессий — только отдельной
командой `--check-sessions` и только при остановленном радаре.

## 9. Расход и метрики: схема A или B ★

Схемы A (постоянный слушатель) и B (проходы по расписанию) отличаются ровно одним — расходом:
памятью, процессором и числом обращений к Telegram. Радар **измеряет это сам**, чтобы решение
«оставить A или переходить на B» принималось по цифрам, а не на глаз.

| Флаг | Что делает |
|---|---|
| `--metrics-interval N` | как часто писать срез ресурсов (память, CPU, нагрузка) в базу. По умолчанию 15 минут; `0` — выключить метрики |
| `--metrics-csv metrics.csv` | файл срезов для Excel: раз в час туда дописывается строка, заголовок не повторяется |

Что попадает в срез (таблица `metrics` в `hits.sqlite3` и строка в `metrics.csv`):
`ts, rss_mb, cpu_percent, uptime_h, msgs_total, msgs_last_hour, api_calls, db_mb,
forwarded_today, accounts, mode`.

**Где смотреть:**

* в Telegram — `/usage`: память с пиком, процессор за сутки, база и WAL, диск под проект,
  сообщения (всего / за час / пик в минуту), API-вызовы, FloodWait, ошибки, находки и
  пересылки по аккаунтам, вердикт и сводка за сутки;
* в консоли — после прохода `--once` печатается `[i] расход: ...` и строка вердикта;
* в Excel — открыть `metrics.csv` (utf-8, разделитель `,`): за сутки набегает 24–96 строк.

**Вердикт и пороги:**

| Вердикт | Когда |
|---|---|
| `A подходит: ресурсов мало` | RSS ≤ 150 МБ и CPU ≤ 5 %, нет FloodWait и ошибок сессии |
| `A возможна, но следи: близко к лимитам lite-контейнера` | 150 < RSS ≤ 250 МБ или CPU ≤ 15 % |
| `рекомендую B (проходы по расписанию)` | RSS > 250 МБ, CPU > 15 %, ≥ 3 FloodWait за сутки или ошибка сессии |
| `н/д: нет данных о ресурсах` | ни psutil, ни `/proc` — измерять нечем (Windows без psutil) |

Пороги — константы в начале `metrics.py` (`RSS_OK_MB`, `RSS_WARN_MB`, `CPU_OK_PERCENT`,
`CPU_WARN_PERCENT`, `FLOOD_WARN_PER_DAY`): под свой контейнер правятся в одном месте.

**psutil не обязателен.** С ним память и CPU точнее; без него на Linux и Android цифры берутся
из `/proc`, а на Windows без psutil остаются «н/д» — тогда вердикт считается по процессору,
FloodWait и ошибкам, и `/usage` честно пишет, чего не видно. Поставить: `pip install psutil`
(в `requirements.txt` строка закомментирована).

**Ретеншн.** Строки `metrics`, `heartbeats` и `errors` старше 30 дней удаляются при старте и
раз в сутки; из `metrics.csv` старые строки убирает тот же механизм. База и файл от этого не
пухнут месяцами.

```bat
start.bat --metrics-interval 5 --metrics-csv out\metrics.csv
start.bat --metrics-interval 0
start.bat --once --catchup 0 --notify bot
```

```bash
python3 monitor.py --metrics-interval 5 --metrics-csv out/metrics.csv   # срезы раз в 5 минут
python3 monitor.py --metrics-interval 0                                # метрики не нужны
python3 monitor.py --once --catchup 0 --notify bot                     # схема B: срез в конце прохода
```

В схеме B разовый проход в конце пишет ещё и **пульс** — накопительными суммами из базы
(счётчики процесса каждый раз новые, а в облаке ещё и контейнер новый). Поэтому бот-панель
видит живость и там: проходы идут — «работает», встали — «⚠️ молчит N мин», а «прочитано
за час» считает все проходы окна. Панель на облачной базе: `cloud_panel.bat` (см. `DEPLOY.md`).

## 10. Готовые наборы команд

```bat
:: ежедневный разовый прогон — присылает свежие находки и выходит
start.bat --once --catchup 20 --category parcel,mixed --max-age 24

:: постоянный радар: тихий режим, находки идут пересылкой боту, пульс раз в 15 минут
start.bat --notify none --category parcel,mixed --max-age 24 --heartbeat 15

:: то же + бот-панель: статус и статистика по командам в личке Telegram
start.bat --notify none --category parcel,mixed --max-age 24 --bot-panel

:: посмотреть, что радар видит, но не отправлять боту
start.bat --once --catchup 50 --explain --forward-dry-run

:: только просьбы отправить груз в Польшу
start.bat --once --catchup 50 --category parcel --only-intent request --only-direction "?->PL"
```

## 11. Настройки в `sources.yaml` (не флаги, но то же самое)

```yaml
defaults:
  profile: chat            # chat | news — профиль по умолчанию
  min_score: 5             # порог совпадения
  catchup: 50              # сколько последних сообщений читать при старте
  order: random            # random | config — порядок обхода чатов
  heartbeat: 0             # пульс живого режима, минут (0 — молча)
  skip_hidden: true        # не брать авторов со скрытым профилем («hidden by user»)

forward:
  to: "@parcel_transfer_bot"
  mode: forward            # forward | copy
  max_per_day: 180         # лимит отправок в сутки с местной полуночи (0 — без лимита)
  fallback: link           # link | skip

# необязательно: несколько аккаунтов (у каждого свой .session и свой лимит)
accounts:
  main:
    session: monitor_session
    forward: {to: "@parcel_transfer_bot", mode: forward, max_per_day: 120}
  second:
    session: second_session
    forward: {to: "@parcel_transfer_bot", mode: forward, max_per_day: 60}
    # enabled: false       # выключить аккаунт, не удаляя настройки
    # proxy: socks5://127.0.0.1:1080

sources:
  - target: "@чат"         # @username, ссылка t.me/..., https://t.me/+hash или -100...
    title: "Как показывать в отчёте"
    profile: chat
    min_score: 4
    catchup: 100
    topics: [502]          # только для форум-чатов, если нужны отдельные темы
    account: main          # какой аккаунт читает этот чат (без строки — первый; auto — по кругу)
```

Один и тот же параметр можно задать и в файле, и флагом: **флаг главнее, но только для этого запуска.**

## 12. Отдельные скрипты (не радар)

| Команда | Что делает |
|---|---|
| `python selftest.py` | быстрая самопроверка расчётов, без аккаунта и без сети |
| `python selftest_monitor.py` | полная самопроверка (матчер, дедупликация, пересылка, фильтры, статистика, несколько аккаунтов, пульс разового прохода) — 153 проверки |
| `python selftest_panel.py` | самопроверка бот-панели и метрик (команды, живость аккаунтов, whitelist, идемпотентность, rate limit, алерты, миграция базы, ретеншн) — 86 проверок, без сети и без psutil |
| `python selftest_metrics.py` | самопроверка метрик расхода и вердикта «A или B» — 65 проверок, без psutil |
| `python deploy/selftest_cloud.py` | самопроверка облачного слоя (подпись R2, состояние, проход, эндпоинты, конфиг деплоя) — 113 проверок, без интернета |
| `cloud_panel.bat` / `./cloud_panel.sh` | бот-панель на облачной базе: скачать `hits.sqlite3` из R2 и запустить `--panel-only` на снимке (схема B в Cloudflare, см. `DEPLOY.md`) |
| `cloud_panel.bat --pull-only` | только скачать снимок базы в `cloud_hits.sqlite3` |
| `python login_wizard.py` | мастер авторизации (то же, что `start.bat --login`): ключи приложения, `.env`, вход по QR, `chat_id` бота |
| `python selftest_login.py` | самопроверка мастера авторизации (валидация ключей, правка `.env`, определение `chat_id`, флаги) — 77 проверок, без сети и без аккаунта |
| `python login_qr.py --session second_session` | вход вторым аккаунтом по QR (то же, что `start.bat --login-qr --session second_session`); без `--session` берётся `monitor_session` |
| `python login_qr.py --ascii-qr` | QR в виде текста в консоли (если картинка не открывается) |
| `python scraper.py --mode history --channels @chan --limit 3000 --out out/raw.jsonl` | разовый сбор истории канала (отдельный инструмент, не мониторинг) |
| `python scraper.py --keywords "кредит,ипотека" --limit 500 --out out/search.jsonl` | поиск по словам в каналах |
| `python scraper.py --help` | все флаги сборщика истории |
| `python web_search.py` | поиск в публичных каналах без аккаунта |

Флаги `scraper.py`: `--channels` (обязательный), `--keywords`, `--regex`, `--mode search|history`,
`--limit`, `--since`, `--until`, `--delay`, `--proxy`, `--session`, `--api-id`, `--api-hash`, `--out`.
